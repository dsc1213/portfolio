HOW I WORK

The strengths I lean on

01
End-to-end ownership
I take a feature from the interface through the API and data layer, then stay with it in production. Knowing both sides means fewer handoffs and decisions that hold up once real traffic hits.
02
Architecture and platform work
Shared component libraries, micro-frontends, SSR foundations, and API contracts that several teams build on — the pieces that stop each squad from re-solving the same problem.

When something breaks, I work through logs and traces in Splunk, Datadog, and New Relic, reproduce the issue, and find the root cause rather than patching the symptom. Test coverage, monitoring, and on-call are part of the job.
04
Working with the team
Code review, design-system and standards decisions, mentoring newer engineers, and working directly with design and product so what ships is what was actually needed.

Things I've built

CARD GAME PWA
Simple Rummy
A multiplayer Indian Rummy engine and client I designed, built, and shipped solo. The server owns all game state — deal, turn order, joker handling, hand validation, and scoring — so the client can never authorise its own move.
  • Authoritative Socket.IO server driving turn state across up to 7 seats per table
  • Redis-backed session store so tables and players survive restarts and reconnects
  • Configurable rule set per table — drop penalties, joker mode, deck count, turn and rejoin timers
  • Installable PWA plus native iOS and Android builds from the same client via Capacitor
  • 100+ active users since launch
Node.js Express Socket.IO Redis PWA Capacitor

FANTASY CRICKET · IN PROGRESS
MyXI
A fantasy cricket platform built end to end — React front end, Express API, PostgreSQL schema, and JWT authentication. The core of the system is a four-tier permission model that scopes every action to the caller's role.
  • Role hierarchy — master admin, admin, contest manager, and player — with server-enforced access control
  • Tournament and contest management: team selection, points rules, and match-by-match scoring
  • Live score ingestion with throttled sync, manual override workflow, and audit logging
  • Per-contest leaderboards and player statistics computed from match data
React Vite Node.js Express PostgreSQL JWT

BILL SPLITTING APP
SimpleSplit
An expense-splitting application built on a single Expo codebase that ships to iOS, Android, and web from one source tree. Backed by Supabase with row-level security enforcing a three-tier permission model.
  • Role hierarchy — app admin, group admin, member — enforced at the database layer
  • Split engine supporting equal, percentage, and custom allocations with fee handling
  • Private bills that expose only the caller's own split to non-payers
  • Net-balance settlement across groups, covered by a Playwright end-to-end suite
